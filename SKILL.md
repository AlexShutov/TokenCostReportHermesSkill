# Token cost report (экономия на локальных LLM)

## Когда использовать
Когда срабатывает ежедневный отчёт в 21:00, или когда пользователь спрашивает про статистику токенов / сколько он сэкономил на локальных LLM.

## Что считается (правило пользователя, 2026-10-18)
- Канонический скрипт: `~/.hermes/scripts/token_cost.py` (крон требует скрипты в `~/.hermes/scripts/`).
- Считаются ТОЛЬКО токены, обработанные локальными LLM (strata :8080, LM Studio, ollama, bionic — любой провайдер, кроме z.ai). Фильтр по таблице `session_model_usage`: исключить строки `billing_provider='zai' OR billing_base_url LIKE '%api.z.ai%'`.
- Токены z.ai coding plan НЕ считаются (идут по лимиту подписки). Экономия = сколько стоили бы локальные токены по ценам z.ai (GLM-5.3-Flash): input $0.15, cached $0.03, output $0.50.
- Копилка (ledger, `~/.hermes/state/token_cost_ledger.json`): суммирует только прирост `last_seen → cur`; удаление сессий (просадка cur) не обнуляет накопленное. Обновляется каждым недрым запуском, включая ручной и тик.
- База суточной дельты (`~/.hermes/state/token_cost_snapshots.json`) хранит значения КОПИЛКИ на 21:00, а не привязку к session_id — прежняя привязка теряла базу при смене/удалении сессии (случилось 2026-10-18).
- Статистика НЕ сбрасывается при смене модели — копилка сквозная.
- Крон-задачи: агентные тратят токены (по умолчанию qwen на strata), но `--no-agent` джобы (rain-golovinsky, token-counter) выполняют скрипт без LLM — ноль токенов.
- Цены z.ai — живые при каждом полном запуске (страница парсится по заголовку таблицы). При неудаче — сохранённая копия `~/.hermes/state/token_cost_prices.json`, в конце сообщения появляется пометка (передавать дословно). Ни сайта, ни кэша — `DEFAULTS` (input $0.15 / cached $0.03 / output $0.50).

## База (append-only) — `scripts/token_cost_db.py`, `~/.hermes/state/token_cost.db`

Каждый запуск (тик крона, полный запуск 21:00, ручной) пишет три таблицы. Ничего не удаляется — только INSERT.

- `runs` — таймстамп запуска, job (`tick`/`commit`/`manual`), cron-задача, профиль, сессия, цены на момент запуска, курс и его источник (`live`/`cache`/`default`), значения копилки.
- `usage_snapshot` — каждое значение source-строки (`session_model_usage`) на момент запуска: session_id, model, billing_provider, billing_base_url, billing_mode, task, plan_class, токены, actual_cost_usd, first_seen, last_seen.
- `increments` — прирост каждой строки между двумя наблюдениями, с временным окном `[window_start, window_end]`. Суточные и сессионные значения считаются **суммированием инкрементов по временным окнам**, а не дельтой от базы снимка — короткая сессия больше не обнуляет «последние сутки» (это был баг: отчёт за сутки печатал $0.00, когда фактическое окно 24 ч было $2.60).
- `plan_class` различает: `zai_plan` / `zai_plan_by_rule` (подписка, в экономию не считается), `zai_paid` (z.ai, но реально списаны деньги — сильный сигнал по `actual_cost_usd`), `local` (любой не-z.ai: strata, LM Studio, ollama, bionic), `unknown` (провайдер не записан). Hermes `billing_mode` для z.ai в этой машине пуст или `chat_completions` — план по нему не определяется, поэтому класс строится по правилу пользователя и помечается `by_rule`.
- Атрибуция времени: `delta` (настоящий интервал между запусками), `first_seen` (строка впервые увиденная — окно first_seen..last_seen), `backfill` (строки, существовавшие до создания базы — атрибутированы точкой `last_seen`, это оценка), `anomaly` (строка уменьшилась ИЛИ исчезла между наблюдениями — в суммы не входит, но остаётся в базе; исчезновение обнаруживается сравнением ключей последнего наблюдения с текущими строками).
- Ограничение (называть в отчёте): инкремент, окно которого пересекает границу суточного окна, считается ЦЕЛИКОМ — при длинном интервале между запусками (крон не работал, машина спала) прирост целиком попадает в день `window_end`.
- Первый запуск базы — `backfill`: токены до создания базы нельзя разложить по времени, они приписаны точке `last_seen`. Это ограничение, не баг; в отчёте оно называется.
- Проверено живым прогоном: база = source-таблица в пределах роста за секунды между запросами (разница 1.4K/374K/2.3K токенов — токены этого же сеанса), двойного счёта нет; тик пишет run с `cron_job='token-counter'` и настоящий delta-инкремент, stdout пустой.

## Переносимость (для чужой машины)

- `TOKEN_COST_CHAT_ID` — Telegram chat id пользователя. Без неё навык использует чат автора (362122320) и отчёт честно говорит, что routing-запись не найдена.
- Обёртки крона решают путь к `token_cost.py` относительно самого файла — абсолютный путь автора не используется.
- Профиль для cron читается из записи задачи в `~/.hermes/cron/jobs.json` (cron НЕ устанавливает `HERMES_PROFILE` — его ставит только kanban-диспетчер).
- `~/.hermes/state/` создаётся при первом запуске; крон исполняет скрипты только из `~/.hermes/scripts/`.

## Output format (standing user rule — keep exactly this shape)
```
Сравнительная цена токенов — только локальные LLM (z.ai не считается)

Сэкономлено за последние сутки (локальные токены по ценам GLM-5.3-Flash):
- вход: <N>M × $0.15 = $<x> (₽<x>)
- кэш-вход: <N>M × $0.03 = $<x> (₽<x>)
- выход: <N>M × $0.50 = $<x> (₽<x>)
- итого $<x> (₽<x>)
- с 21:00 предыдущего запуска: $<x> (₽<x>)
- в среднем за час: $<x> (₽<x>)

За текущую сессию (локальные токены):
- вход: ...
- кэш-вход: ...
- выход: ...
- итого $...
- длительность сессии: <N дня/дня/дней N час/часа/часов N минута/минуты/минут>
- по базе за эту сессию: <N>M / <N>M / <N>M — только если база видит меньше source-таблицы (часть строк была до создания базы или plan unknown)

Не учтено (z.ai coding plan): <N>M токенов

По дням (локальные токены):
- <дата>: <N>M = $<x> (₽<x>)
- ... (последние 4 дня)

<пометка про базу: суточное окно = сумма инкрементов по временным окнам из append-базы; строки, существовавшие до создания базы, атрибутированы точкой last_seen — это оценка>

курс взят из «Плати по миру»
```
- Суточное окно и «по дням» считаются из базы (`token_cost_db.py`), а не дельтой от снимка 21:00. Снимок 21:00 остаётся (его пишет только `--commit`), но отчёт по нему больше не считает сутки.
- Рубли: курс — https://platipomiru.com («Плати по миру»), НЕ курс ЦБ. Тариф — «Для подписок». Курс обновляется ТОЛЬКО на автоматическом запуске (`--commit`); прямой запуск читает кэш, при его отсутствии — `DEFAULT_RATE` (95,35). Курс ищем только рядом со словом «курс» — иначе парсер схватит цену карты (2 990₽).
- Если сессия идёт на z.ai, блок «За текущую сессию» будет нулевым — это нормально, не «чинить».
- Блок про только что созданную копилку (первый запуск) передавать как есть.

## Cron setup (live)
- `token-cost-daily` (id `a4f0bff6e8dc`): agent-enabled, скрипт-обёртка `token_cost_commit.py` (`--commit`) как pre-run, 21:00 МСК, deliver `origin`, skills `token-cost-report`. Преран-вывод агент форматирует и НЕ перезапускает скрипт (второй запуск обнулит суточную дельту).
- `token-counter` (id `ee33ad768298`): каждые 10 минут, `--no-agent` (скрипт = задача, без LLM — ноль токенов), скрипт `token_cost_tick.py` (`--tick`: обновить копилку, stdout пуст = тихо), deliver `local` + failure-deliver `local` — в Telegram не спамит.
- Snapshot и базу 21:00 пишет ТОЛЬКО `token_cost_commit.py`. Ручной запуск (`token_cost.py` без флагов) читает и пополняет копилку, но базу не двигает. `--dry-run` не пишет вообще ничего.
- Доставка ежедневного отчёта — ровно одно сообщение: `cat <<'TXT' | python3 ~/.hermes/scripts/single_message.py token-cost 362122320`, после строки `sent ...` агент отвечает ровно `[SILENT]`.

## Pitfalls
- `messages.token_count` NULL — только агрегаты из `session_model_usage`; БД открывать `mode=ro` (гейтвей держит write-локи).
- Фильтр локальности — по `billing_provider`/`billing_base_url`, НЕ по имени модели: в одной сессии бывают строки нескольких моделей/провайдеров, а `sessions.model` хранит только последнюю.
- Копилка считает только токены, увиденные после её создания (2026-10-18): ранее удалённые сессии в «за всё время» не входят — это недооценка, не баг.
- Суточная дельта считается от копилки, поэтому переживёт смену сессии, удаление сессии и смену модели.
- При тестах — `--dry-run` (не пишет ничего: ни копилку, ни снимок, ни кэши).
