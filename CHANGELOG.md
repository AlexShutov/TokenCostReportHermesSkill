### Append-база статистики + фикс суточного окна (короткая сессия)
- Новый `scripts/token_cost_db.py`: append-only SQLite (`~/.hermes/state/token_cost.db`), три таблицы — `runs` (таймстамп каждого запуска, job, cron-задача, профиль, сессия, цены и курс на момент запуска), `usage_snapshot` (каждое значение source-строки на момент запуска), `increments` (прирост каждой строки между наблюдениями с временным окном). Ничего не удаляется — только INSERT.
- Суточное окно и «по дням» считаются суммированием инкрементов по временным окнам, а не дельтой от снимка 21:00. Баг: при короткой сессии «за последние сутки» печатал $0.00, хотя фактическое окно 24 ч было $2.60 (замерено живым прогоном на этой машине).
- `plan_class` различает z.ai coding plan и оплату по факту: `zai_plan_by_rule` (правило пользователя), `zai_paid` (списаны деньги — сильный сигнал по `actual_cost_usd`), `local` (любой не-z.ai), `unknown`. `billing_mode` для z.ai в этой машине пуст или `chat_completions` — по нему план не определяется.
- Атрибуция времени: `delta` (настоящий интервал между запусками), `first_seen`, `backfill` (строки до создания базы — атрибутированы точкой `last_seen`, это оценка), `anomaly` (уменьшение/исчезновение строки — в суммы не входит, но остаётся в базе).
- Ограничение честно называется в отчёте: токены до создания базы нельзя разложить по времени.
- Проверено живым прогоном: база сходится с source-таблицей в пределах роста между запросами (разница 1.4K/374K/2.3K токенов — токены этого же сеанса), двойного счёта нет; тик пишет run с `cron_job='token-counter'` и delta-инкремент, stdout остаётся пустым.

### Только локальные LLM + копилка экономии (правило пользователя)
- Статистика считает ТОЛЬКО токены локальных моделей (фильтр `billing_provider`/`billing_base_url` по NOT z.ai в `session_model_usage`); токены z.ai coding plan не считаются — они идут по лимиту подписки.
- Экономика = сколько стоили бы локальные токены по ценам z.ai (GLM-5.3-Flash): input $0.15, cached $0.03, output $0.50. Копилка-леджер (`token_cost_ledger.json`) суммирует только прирост, удаления сессий не обнуляют.
- База суточной дельты хранит значения копилки на 21:00, а не привязку к session_id — переживает смену/удаление сессии и смену модели.
- Формат: «за всё время» убрано, вместо него разбивка «По дням» за последние 4 дня.
- Cron: token-cost-daily (21:00, --commit через token_cost_commit.py) + token-counter (каждые 10 мин, --no-agent, token_cost_tick.py — обновление копилки без LLM).
