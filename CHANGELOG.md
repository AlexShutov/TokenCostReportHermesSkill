## 20.10.2026 — баг: блок плана считал z.ai-токены вместо локальных

Критичный (меняет доставляемый результат — смысл навыка):
- **Смысл навыка — экономия на локальной LLM относительно z.ai coding plan.** Источник
  инкрементов блока плана фильтровал `ZAI_PLANS` и считал сами z.ai-токены, то есть процент
  плана строился по z.ai, а не по локальным токенам. Теперь источник фильтрует
  `plan_class='local'` (`STAT_CLASSES`): процент — эквивалентное потребление плана локальными
  токенами по мультипликаторам эквивалентной модели. z.ai-строки остаются в базе (логируются),
  но в кредиты не входят и называются отдельной строкой лога.
- Замер на живой базе: было 5.2% (2297.6 кредитов по z.ai-строкам), стало 47.7% (21125.0
  кредитов по локальным строкам), z.ai-строки названы: 23 (73.73M токенов) — логируются, не
  считаются.
- Тесты переведены под правило; Max-переполнение в чистой установке проверяется локальным
  рядом (прежний z.ai-ряд больше не может вызвать переполнение — проверка проходила по
  неверной причине).
- Источник закрывает соединение после каждого вызова: тест обязан давать фабрику соединений,
  иначе второй вызов того же источника падает.
- `logged_zai` обязан использовать одно определение исключённых атрибуций для обоих путей:
  путь базы считал anomaly-строку, путь ядра — нет, цифры расходились (2 против 1).

Тесты: 45 + 91 + 29 + 17 = 182; чистая установка 39 проверок.
